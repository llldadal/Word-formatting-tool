# v0.1 容器树与 DOCX 映射草案

这份草案约定公共数据怎样表达布局，以及导出时怎样转换到 DOCX。v0.1 的范围已经收敛为单页、单栏、最多一层容器嵌套。公共类型定义在 shared/DocumentSnapshot.h 和 shared/LayoutResult.h 中。XML 映射仍为设计提案，实际 Word 中的显示和编辑需要按范围内的用例验证。

## v0.1 的容器范围

逻辑根节点用于组织文档。嵌套深度从顶层内容容器开始计数。

```text
文档根
├── 文本容器 A
│   ├── 图片 P
│   ├── 图片 Q
│   └── 小文本容器 B
└── 文本容器 C
```

A 和 C 是顶层容器。P、Q、B 是一层子容器，它们的 children 为空。一个父容器可以包含多个子容器。普通分组容器也遵守相同的深度计数规则。

顶层正文按纵向顺序单栏排列。子容器在父内容区中作为固定障碍，正文可以在其左右绕排。父容器的高度至少容纳自己的文字、子容器及底部内边距。

编辑器的纸张尺寸固定，排版继续生成完整内容，画布显示超出纸面的部分。文档模块在增加节点和更换父节点时校验嵌套深度，排版和导出对收到的快照也按此约定检查。

## 模块之间的依赖

| 模块 | 读取的数据 | 输出或修改的数据 |
|---|---|---|
| 文档 | 用户提交的内容和布局要求 | 容器树、资源、文档版本和 DocumentSnapshot |
| 排版 | DocumentSnapshot | LayoutResult，包含实际区域和文字片段 |
| 导出 | 同一版本的 DocumentSnapshot 和 LayoutResult 中的几何数据 | DOCX 文件或明确的兼容性错误 |

文档中保存文字、段落语义、格式和布局意图。排版结果通过 containerId 关联源节点，提供实际的容器框、内容区、占位区和图片位置。导出模块在这两份公共数据之间建立关联，XML 的生成规则由导出模块负责。

导出测试可以直接在 C++ 中构造输入快照与容器矩形。排版测试使用同样的快照和标准结果。两边都能基于固定数据独立开发。

## 容器需要表达的布局意图

类型继续表示文本、图片、分组。ContainerNode 的 placement 字段使用 PlacementMode，表达节点参与顺序流，或作为固定的绕排障碍。

| 属性 | 建议值 | 含义 |
|---|---|---|
| placement | Flow、Floating | 节点参与顺序流，或作为固定位置的绕排障碍 |

文本容器中的图片和小文本块默认采用 Floating，它们的位置相对父容器内容区固定。顶层普通正文默认采用 Flow。

placement 属于布局语义，XML 元素名由导出模块选择。分组在本版本中按纵向顺序组织内容。

## 内容映射

| 我们的数据 | DOCX 的表达 | 数据来源 |
|---|---|---|
| 文档根 | w:document / w:body | 文档快照 |
| 普通段落 | w:p | 段落范围和正文 |
| 段落格式 | w:pPr | 对齐、缩进、行距、段前段后距 |
| 正文、文档标题、章节标题 | w:pStyle，以及 styles.xml 中的样式 | 语义角色、标题级别 |
| 同一种字符格式的连续文字 | w:r / w:rPr / w:t | 合并继承后的字符格式及文字 |
| 独立成块的图片 | 独立 w:p 中的 w:drawing / wp:inline | 资源、显示尺寸和顺序 |
| 作为绕排障碍的图片 | w:drawing / wp:anchor，其中包含图片 DrawingML | 资源、实际区域、外边距 |
| 作为绕排障碍的小文本块 | wp:anchor 下的文字形状，内容位于 w:txbxContent | 段落、格式、实际区域、内外边距 |
| 纵向分组 | 依次展开子节点，并换算其间距和缩进 | 子节点顺序、几何约束与实际区域 |
| 原始图片资源 | word/media 下的文件，以及 document.xml.rels 中的关系 | 资源表 |
| 页面尺寸和页边距 | w:sectPr 中的 w:pgSz、w:pgMar | 页面设置 |

DOCX 中的段落、格式片段和文本分别由 p、r、t 表达。多个格式片段仍可以属于同一段正文。文字分片的 sourceRange 用于回指原文，导出时按段落与格式范围组织文本。[微软文档结构说明](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)

## 固定子容器的定位与绕排

1. 源节点保留相对父内容区的位置。排版模块把它换算成纸张坐标，输出实际矩形。
2. 导出模块在父文本容器输出的第一个段落中放置浮动对象锚点。空文本容器也生成一个空段落，作为可编辑的内容及锚点承载位置。
3. 浮动对象的初始位置采用排版结果中的纸张坐标，尺寸采用容器框尺寸。父子关系已经通过坐标换算体现在位置上。
4. 矩形绕排写入 wp:wrapSquare，并设置 wrapText="bothSides"。容器的四边外边距映射为对象与周围文字的距离。
5. 小文本块内部继续导出可编辑的段落和格式。其 padding 映射为文字形状的内部边距。
6. 作为浮动文本框导出的小文本子容器保持为叶节点，其内部包含自己的正文和段落。

浮动对象在文件中锚定到段落，同时可以相对页面定位。这个锚点是导出的结构关系，编辑器中的子容器位置继续由父内容区决定。[浮动对象与锚点](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.wordprocessing.anchor?view=openxml-3.0.1)

矩形绕排支持两侧排字及四边文字距离。[矩形绕排](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.wordprocessing.wrapsquare?view=openxml-3.0.1)

## 盒模型与单位

| 项目 | 本项目的约定 | 导出处理 |
|---|---|---|
| 容器宽度 | border-box，包含 padding | 浮动文本框使用实际框宽，内部设置 padding |
| 正文容器左右 padding | 缩小文字可用宽度 | 顺序段落用左右缩进，文本框用内部边距 |
| 正文容器上下 padding | 加入容器高度 | 顺序段落在首尾段落处合并为块间距，文本框使用内部边距 |
| 相邻容器 margin | 两边直接相加 | 先算出目标间距，再写入段落间距 |
| 浮动对象 margin | 正文需要避让的距离 | 写入对象的四边绕排距离 |
| minimumHeight | 容器高度下限 | 文本框使用本次实际高度，顺序段落按内容和间距表达 |
| 几何单位 | 公共数据使用固定的文档逻辑像素，96 个单位为一英寸 | 1 单位对应 15 twip 或 9525 EMU，按目标字段取整 |
| 字号 | 公共数据使用 pt | w:sz 用半点表示，例如 12 pt 写为 24 |

普通顺序段落没有通用的“自动增高容器”对象。这里表达的是内容和排版规则，后续高度由 Word 计算。固定文本框的增高行为与我们容器的弹性高度规则应单独验证。

Word 的相邻段落间距按相关值的较大者计算，因此本项目的外边距相加规则需要在导出时先求和。对于纯块间距，可以将目标值放在前块末段的 after，并将后块首段的 before 设为零，再结合行距验证最终间距。[段落间距规则](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.spacingbetweenlines?view=openxml-3.0.1)

字号的半点单位来自 WordprocessingML 的字体大小定义。公共类型使用固定文档 DPI 进行尺寸换算，屏幕缩放由 UI 另行处理。[字体大小单位](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.fontsize?view=openxml-3.0.1)

## 验收题目与映射

| 题目 | 容器树应表达的意图 | DOCX 映射方案 | 验证重点 |
|---|---|---|---|
| 01 标题和两段正文 | 顺序文本块 | 三组段落及对应样式 | 正文顺序、格式、块间距 |
| 02 单图嵌入正文 | 正文中有一张固定浮动图片 | 连续段落加一个两侧绕排的浮动图片 | 图片位置、两侧绕排、编辑后仍连续 |
| 03 双图嵌入正文 | 正文中有两张固定浮动图片 | 连续段落加两个浮动图片 | 两图位置、可用区域、文字顺序 |
| 04 图片在正文底部 | 顺序文本块后接独立图片块 | 段落后接独立的行内图片段落 | 图片在正文之后、整体间距 |
| 06 大正文右下角嵌套小段落 | 正文中有一个固定浮动文本子节点 | 正文段落加一个带矩形绕排的文本框 | 正文绕开文本框，内部文字可编辑，优先实测 |

v0.1 使用原题编号 01、02、03、04、06。原第 05 题归入后续多栏版本的参考资料。还需要增加多种文字格式、页面溢出和嵌套深度校验用例。

第 06 题中，大正文采用主文档中的普通段落，小段落采用浮动文本框。源容器树的父子关系在导出时转换为锚点和实际位置。

## 需要在冻结前验证的边界

- 微软的实现说明记录了文本框内容嵌套的限制。当前一层嵌套对应正文加浮动文本框，重点验证第 06 题的导出和持续编辑。[微软文本框实现限制](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/dc83bfa3-db21-4eb4-b3c0-63b11f2575d3)
- 正文超出编辑器单页时，完整正文写入 DOCX，由 Word 接续排版。浮动对象本身超出纸面时，位置如何转到后续页还没有冻结。草案建议先返回带容器 ID 的兼容性错误，待确认后增加位置降级或分页映射。
- 对单栏正文的缩进、内外边距、最小高度如何换算到 Word，需要补充用例。
- 范围内的 DOCX 用例尚未在实际 Word 中逐一验证。需要检查正常打开、持续编辑、图片及文本框的绕排，以及格式和语义。

## 后续多栏版本

论文式双栏使用同一份连续正文，并在节属性中设置 w:cols。Word 负责栏间接续，标题单栏与正文双栏之间需要通过分节表达范围。跨栏图片还涉及多个栏的共同避让、跨栏区域前后的正文接续，以及分页和栏高规则。[DOCX 原生分栏](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.columns?view=openxml-3.0.1)

## 并行开发时共同遵守的内容

文档模块交付稳定的源数据，排版模块交付按 ID 关联的实际几何结果，导出模块按照本表完成 DOCX 映射。公共约定包括字段含义、单位、坐标系、布局模式、版本关联和兼容性处理。

导出模块只需要读取 LayoutResult 中与容器和图片有关的普通几何数据。QTextLayout、QTextLine 和逐行文字片段用于 Qt 预览与交互，Word 根据连续段落及绕排规则重新排字。

进入并行开发前，建议优先验证第 06 题，并确认超页浮动对象的导出处理规则。各模块可以先按公共类型建立自己的输入与输出样例。
